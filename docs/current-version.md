## 两种运行条件

默认 `demo` 模式可以无密钥启动并查看内置样例。`model` 模式需要用户自行配置模型接口；模型负责意图与解释，工具负责业务事实，完整图表数据不进入模型上下文。语音服务也需单独配置。

动态插入、重排、MRP 计算与模拟下发还需要本机独立 SQL 副本和 `dev-config/native-demo/worker.py`。GitHub 不携带数据库、备份、业务凭据、运行结果目录或生产连接配置，克隆仓库不会自动获得完整计算环境。缺少 worker 时，相关操作会提示当前不可计算。

Compose 将 `NATIVE_DEMO_RUNTIME_PATH`（默认 `./runtime/native-demo`）挂载为 `/demo-runtime`。worker 使用无网络、无宿主端口的 SQL 容器，数据库名为 `ApsIsolatedDemo`；接入前需自行准备匹配的隔离样例库及原过程。不得将它指向正式业务数据库。原过程执行后回滚，模拟下发不代表正式 MES 写入。

公开副本继续统一替换样例订单编号；配置与内置结果的输入指纹已随之更新。运行环境相关脚本和本机工作记录没有直接复制到公开仓库，原开发工程保持不变。
